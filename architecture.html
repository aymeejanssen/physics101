Technical architecture and implementation strategy

Build System

A production-ready architecture for adaptive curriculum, AI tutoring, textbook intelligence, vector search, simulations, assessments, and institution-scale deployment.

Recommended Stack

Start with a modular monolith to move fast, then split simulation, AI orchestration, ingestion, and analytics services when usage demands it.

Frontend

  • Next.js with TypeScript and React Server Components.
  • Tailwind or token-based CSS modules for design consistency.
  • Three.js / React Three Fiber for 3D physics visuals.
  • D3 or Observable Plot for graphs and learning analytics.
  • MathJax or KaTeX for equations.

Backend

  • Node.js/NestJS or Python/FastAPI for API services.
  • PostgreSQL as primary relational database.
  • Redis for sessions, queues, rate limits, and tutor memory cache.
  • Object storage for textbook chunks, images, simulation assets, and exports.
  • Background workers for ingestion, grading, and report generation.

AI and Search

  • LLM orchestration layer with provider abstraction.
  • Postgres + pgvector for MVP vector search.
  • Hybrid retrieval: vector similarity + keyword + graph constraints.
  • Structured output validation for tests, roadmaps, and tutor actions.
  • Evaluation harness for hallucination, pedagogy, and problem correctness.

Data Flow

The system treats learning as a loop: diagnose, teach, practice, observe, update mastery, unlock next concept.

1. Intake

Adaptive diagnostic

Questions are selected by current estimate of mastery, prerequisite graph position, and uncertainty.

2. Roadmap

Curriculum planner

Graph traversal builds a route from current state to target goal with weekly workload and mastery gates.

3. Lesson

Tutor and content retrieval

Relevant concept nodes, textbook summaries, formulas, examples, and misconceptions are retrieved for the tutor.

4. Practice

Adaptive generator

Problems are generated or selected according to weakness, difficulty, problem type, and recent errors.

5. Mastery

Learning model update

Performance updates concept mastery, misconception flags, confidence, and review scheduling.

AI Architecture

The tutor should not be one giant prompt. It should be a controlled learning system with retrieval, tools, structured outputs, and evaluation.

Planner

Chooses next lesson, review item, simulation, or problem based on mastery, uncertainty, and goal deadline.

Retriever

Finds concepts, formulas, textbook summaries, prior mistakes, and similar worked examples.

Tutor

Uses Socratic questioning by default, escalates hints gradually, and only gives full solutions after effort.

Problem Generator

Creates adaptive conceptual, computational, derivation, exam, and challenge problems with rubrics.

Evaluator

Grades solutions, checks derivation validity, detects misconceptions, and updates mastery records.

Safety and Quality Layer

Validates math, citations, difficulty, solution correctness, and whether the tutor gave away too much too soon.

Scalability Strategy

Begin simple, then separate hot paths. The expensive work is AI generation, simulation compute, embeddings, and grading.

MVPNext.js app, PostgreSQL + pgvector, Redis queue, object storage.Fastest path to a real product with authentication, learning state, and AI features.

Authentication and Roles

Authentication must support individual learners first, then teams and institutions.

Learner

Personal roadmap, mastery, tutor memory, exams, certificates, notes, and simulation history.

Instructor

Cohort dashboard, assigned roadmaps, custom problem sets, grading review, and concept analytics.

Institution Admin

Licensing, SSO, seat management, privacy settings, reporting, and LMS export.

Implementation preference: ship as a modular monolith first, with clean service boundaries inside the codebase.
